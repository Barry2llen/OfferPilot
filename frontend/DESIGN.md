# OfferPilot 前端与客户端设计

本规范替代旧的 MiniMax 风格参考。产品保留黑白主色，以清晰的层级、稳定的布局和可预期的交互建立亲和感。

## 视觉基础

- 浅色：白色画布 `#FFFFFF`、侧栏 `#F7F7F8`、正文 `#18181B`、边框 `#E4E4E7`。
- 深色：画布 `#121212`、表面 `#1C1C1E`、正文 `#F5F5F5`、边框 `#3A3A3C`。
- 主操作随主题反色；语义状态色只用于成功、错误、警告和信息反馈。
- DM Sans 配合系统中文字体；代码使用系统等宽字体。正文 15px，常规控件 14px，辅助信息 12px。
- 使用 4/8px 间距体系、8–16px 圆角和细边框。避免装饰性渐变、发光阴影和无必要的卡片嵌套。

## 设备布局

| 可用视口宽度 | 导航与内容 |
| --- | --- |
| >= 1200px | 主侧栏默认 232px，可拖动右边缘在 200–360px 间调整（双击复位，宽度保存在 `offerpilot.sidebar.width`），会话历史并入同一侧栏；聊天限宽；简历详情默认只显示解析，打开原件后解析与原件双栏；岗位输入与记录双栏 |
| 768–1199px | 64px 图标栏；会话历史按需打开；简历详情通过同一按钮在解析与原件之间切换 |
| < 768px | 五项底部导航；单列内容；历史、表单和待回答问题使用全屏面板 |

断点依据视口而非设备类型。改变断点不会清空当前输入或待回答草稿。根布局使用动态视口和 VisualViewport，高度随软键盘可见区域变化，底部保留安全区。

## 主题与设置

`/settings/appearance` 提供浅色、深色、跟随系统和语言设置。默认跟随系统；用户选择保存在 `offerpilot.theme`，首屏脚本在 React 启动前应用主题。手动选择覆盖系统偏好；存储不可用时保留本次会话的选择。

供应商、模型选择、高级设置沿用现有 API。模型名称与图片能力优先展示，协议、思考和 JSON 参数放入高级区域；原生字段校验失败时，立即展开高级区域，让浏览器定位错误字段。模型选择器和图片/附件选择器复用可访问的抽屉；模型菜单的水平对齐独立于触发器样式，空简历库右上角的入口使用右对齐，避免菜单越出视口。供应商列表与模型面板之间的分隔线始终撑满设置内容区高度。

所有下拉统一使用 `app/components/ui/select.tsx`：按钮触发 `role="combobox"`，弹出 `role="listbox"`，支持方向键、Home/End、Enter、Escape，靠近视口底部时向上展开。文本输入框、文本域获得焦点时不绘制边框、描边或外发光；按钮和链接仅在键盘焦点时显示描边。品牌名右侧显示版本号。

## 聊天交互

- 输入区为胶囊形：左侧 `+` 打开上传/文件库菜单，中间为输入框，右侧依次为思考强度、运行中的停止按钮和圆形发送按钮。草稿换行或带附件时切换为文本在上、操作在下的两行布局，清空后恢复单行。运行中可继续编辑并加入队列。
- 思考强度只作用于本次请求（`thinking_override`）；“默认”表示沿用模型选择中保存的设置，不发送覆盖值。模型选择器保留在顶部栏。
- 桌面 Enter 发送，Shift+Enter 换行；手机 Enter 换行，Ctrl/Cmd+Enter 发送。
- 输入法组合态以及 keyCode 229 不触发发送。
- 工具、思考和待回答状态沿用现有流协议。手机显示问题摘要，点击后进入独立回答面板；关闭面板保留选项、手填答案和补充说明。回答提交失败时通过面板上方的 Toast 显示错误，保留草稿与面板并允许重试。
- 当前阅读位置优先。只有用户跟随底部时，新消息和待回答内容才滚动到最新位置。
- 业务状态继续由 AppProvider/useChatStream 管理。导航关闭订阅，显式停止才取消运行；不另建消息解析器。

## 资源与可访问性

简历库支持名称搜索、解析状态筛选、上传时间/名称排序。已有简历时通过主按钮打开上传面板；空库保留上传引导。文件库使用紧凑列表，区分空库和无搜索结果。岗位输入保留文字、URL、图片组合；进度区在开始分析后出现并保留位置，未开始时不留空白。分析结果中的事实类型、需求块类型和重要度通过双语资源本地化，未知类别以可读文本回退。

原生 dialog 提供焦点约束、Escape、背景隔离和焦点恢复。确认删除和普通表单共用基础层。抽屉进入/退出 220ms，控件反馈 120ms；CSS 和 Motion 都尊重 reduced motion。Toast 通过非模态 popover 保持在对话框上方。

## Electron

窗口默认 1280×820，最小 640×560。保留标题栏拖拽区；宽度低于 768px 且侧栏品牌隐藏时，Windows/Linux 非聊天页面由 AppShell 在标题栏留白中提供拖拽区，聊天页继续使用现有顶部栏，浏览器页面不显示额外区域。Windows/Linux 由前端自绘最小化、最大化/还原、关闭按钮（每个 46×72px，悬停变色，关闭悬停为红色），按钮底边与 72px 顶部栏分隔线对齐；对话框打开时按钮在对话框内重复渲染以保持可用。macOS 保留原生红绿灯。页面的 theme-color 元数据驱动原生背景色；preload 只暴露 apiBaseUrl、platform 和 windowControls 包装函数，contextIsolation/nodeIntegration 安全配置不变。

## 验证边界

前端检查：lint、typecheck、Vitest、生产构建。Electron 检查：lint、Node 测试、build:electron。渲染验证使用 IAB 与 Windows 原生窗口，覆盖中英文、主题、响应式布局及真实组件消费的隔离模拟 SSE。

隔离示例用于验证视觉与交互，不代表真实模型供应商、文件解析或打包安装器的端到端验收。真实触屏软键盘、Safari/Firefox 和 Linux 原生窗口需在对应设备上继续验证。

此次修改不改变后端 API、数据库、SSE 协议或打包目标。Vite 增加已有 /context-compaction-settings 接口的开发代理。
